# Додавання, оновлення і відновлення

## Новий інструмент

1. Створи окремий репозиторій лише коли є код. Додай README.md, AGENTS.md, .gitignore та перевірки, доречні для застосунку.
2. Для простого HTML використовуй index.html у корені або docs/index.html. Налаштуй Pages на відповідну папку. Для застосунку зі збіркою – GitHub Actions із перевіркою перед deploy.
3. Використовуй відносні шляхи до ресурсів. Не припускай, що застосунок розташований у корені домену.
4. Додай посилання на головний портал: `<a href="https://roman-khoroshko-tech.github.io/">← До інструментів</a>`. Це тільки навігація: робота застосунку не повинна залежати від завантаження порталу.
5. Після перевірки опублікованого застосунку додай запис у tools.json. Приклад:

```json
{
  "id": "my-calculator",
  "name": "Інженерний калькулятор",
  "description": "Яку саме задачу розв’язує інструмент.",
  "category": "Розрахунки",
  "url": "https://roman-khoroshko-tech.github.io/my-calculator/",
  "icon": "calculator",
  "version": "1.0.0",
  "status": "ready",
  "order": 30
}
```

Доступні іконки: plc, chart, calculator, book. Статуси: ready – доступний; beta – тестова версія; development – у розробці; planned – заплановано. Для непублікованих записів url: null; version можна пропустити. id має бути унікальним, order – числом. Нові категорії з’являються автоматично. Менше значення order показується вище. Не додавай непротестовану адресу як ready/beta.

6. npm test → npm run build → commit → push. Перевір Actions і сайт.

## Робота через Codex

Приклад завдання: «У репозиторії порталу додай у tools.json інструмент [назва, URL, опис]. Перевір доступність адреси, каталог і мобільний вигляд. Репозиторії застосунків не змінюй».

Для редактора: «Працюй тільки в MFC710-PLC-editor. Реалізуй [зміна], виконай його перевірки й збірку. Портал не змінюй, окрім версії в каталозі, якщо я це замовив».

## Перша інтеграція MFC710

Вихідна версія пакета – 0.1.0-rc.1 (за package.json). Назва папки резервної копії «1.0» не змінює фактичну версію пакета.

Редактор використовує build-pages.cjs: він формує автономний HTML і docs/index.html. Публікуй тільки після npm test, npm run build, npm run check:pages. Наявні браузерні тести редактора потребують Playwright. Не стверджуй, що вони пройшли, якщо залежність відсутня.

Посилання «До інструментів» слід додати у вихідний dist/index.html, потім повторити збірку; не правити тільки згенерований docs/index.html. Вбудовані інструкції виробника мають власні авторські права – збережи THIRD_PARTY_NOTICES.md.

Для Pages редактора з наявним пакетом: Settings → Pages → Deploy from a branch → main → /docs. Його поточний CI перевіряє код, але не блокує окремий branch-deploy Pages; для критичних оновлень використовуй PR і дочекайся CI перед merge. За потреби пізніше переведи його на перевірюваний Actions deploy.

Після підтвердження адреси редактора у tools.json встанови url: https://roman-khoroshko-tech.github.io/MFC710-PLC-editor/ і status: beta. Назва beta відображає передрелізний статус; це не підтвердження придатності для налаштування реального ПЧ без перевірки.

## Критичні зміни й відкат

Працюй у гілці, відкривай PR, перевіряй CI і браузер перед merge. За можливості увімкни правила захисту main із required status check check. Портал і кожен застосунок мають власні релізні теги.

Для повернення: git status → git log --oneline → git revert COMMIT_SHA → npm test → npm run build → git push. Це створює зворотний commit і зберігає історію. Не використовуй reset --hard або force push для спільної main. Для редактора після revert виконай його власну збірку і перевірку Pages, якщо згенеровані файли не відновилися тим самим commit.

## Перевірка UI

Перевір 390×844, 768×1024 і 1440×900: відсутність горизонтального прокручування, читабельність, пошук назви й українського опису, поєднання категорії та статусу, порожній результат, темна/світла тема і її збереження після reload. Перевір керування клавіатурою Tab, Enter і /. Для помилкового JSON або HTTP-помилки має бути повідомлення і кнопка повторного завантаження. Після відновлення конфігурації повторний запит має показати каталог.
